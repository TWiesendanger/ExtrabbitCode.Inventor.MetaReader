iLogic rules are stored inside the Inventor document itself. MetaReader reads them straight from
the file - **no Inventor needed** - so you can see at a glance whether a part, assembly or drawing
carries automation, what each rule does, and which events run it.

## In the sidebar

Next to the [category badge](/docs/categories), two outlined chips show what the document contains:

- **iLogic** - the document has at least one rule. Hover it for the list of rules (suppressed ones
  are marked); click it to open the iLogic tab.
- **N triggers** - the document has event triggers. Hover it to see which event runs which rule,
  e.g. *Before Save Document → UpdateDescription*.

<ThemedImage slug="app__ilogic-sidebar" alt="The sidebar of a part with iLogic: a General category badge followed by outlined 'iLogic' and '2 triggers' chips" className="max-w-sm mx-auto" />

The category badge is solid because it says what the document *is*; the iLogic chips are outlined
because they say what it *contains*.

## The iLogic tab

The **iLogic** tab lists every rule in the order of the iLogic browser, each in its own card:

- **Options** that differ from iLogic's defaults - *Suppressed*, *Doesn't run automatically*,
  *Straight VB code*, *Fires dependent rules immediately*, *Not silent*.
- **Triggers** - the events that run the rule.
- **The rule's code**, read-only, with a **Copy code** button.

<ThemedImage slug="app__ilogic-panel" alt="The iLogic tab with three rule cards: one with a Before Save trigger, one suppressed, one that doesn't run automatically, each showing its code" />

Triggers that point at a rule *not* stored in the document - an **external rule** - are listed in
their own card at the end. External rules live in separate `.iLogicVb` files, so their code isn't
part of the document.

## From the command line

The [command-line tool](/docs/command-line) shows the same information:

- `invmeta info` adds an **iLogic** section with the rule names, their options and the triggers.
- `invmeta ilogic` prints every rule with its code.
- `invmeta json` includes an `iLogic` object (`hasRules`, `rules` with `text` and options, and
  `triggers`), handy for auditing many files at once.

## How it works

Inventor marks a document that has rules with a small `_iLogic` property set and removes it again
when the last rule is deleted, so detecting iLogic costs nothing. The triggers are a second property
set, one entry per trigger. The rules themselves - names, code and options - are stored as document
attributes in one compressed segment of the file, which MetaReader only unpacks when the marker says
rules are there. The byte-level details are in the repository's
[file format notes](https://github.com/TWiesendanger/ExtrabbitCode.Inventor.MetaReader/blob/master/docs/INVENTOR-FILE-FORMAT.md).
